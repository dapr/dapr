# Dapr 1.18.8

This update contains the following bug fixes and improvements:
- [Cancelled actor calls broke turn-based concurrency](#cancelled-actor-calls-broke-turn-based-concurrency)

## Cancelled actor calls broke turn-based concurrency

### Problem

When a caller cancelled an actor call that was waiting for the actor's current turn to finish, the sidecar could send other waiting calls to the app while that turn was still running. Several calls could then run at once on the same actor ID, with reentrancy enabled or disabled.

### Impact

You were affected if callers of your actors cancel calls, for example through client timeouts or abandoned requests, while other calls to the same actor are waiting. Turns that read, modify and write actor state could run at the same time and overwrite each other's changes. Removing an actor timer while its call was waiting behind a running turn caused the same problem.

### Root Cause

Each actor keeps a queue of calls waiting for its lock, and the running turn is at the front of that queue. When a waiting call was cancelled, it removed the front of the queue, which was the running turn, rather than its own entry. The next waiting call then started while the running turn was still executing.

### Solution

Only the running turn removes calls from the queue. A call cancelled while waiting is marked as abandoned and skipped when the running turn finishes, so each actor runs one turn at a time again.
