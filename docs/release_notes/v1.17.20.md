# Dapr 1.17.20

This update contains the following bug fixes and improvements:
- [Pub/sub deliveries without trace context were not traced](#pubsub-deliveries-without-trace-context-were-not-traced)

## Pub/sub deliveries without trace context were not traced

### Problem

When a pub/sub message arrived with no W3C trace context (no `traceparent` and no legacy `traceid`), the sidecar started no span for the delivery and sent no `traceparent` to the app.

### Impact

Messages published outside Dapr, raw payload (`rawPayload: "true"`) subscriptions and messages re-queued from a dead letter topic did not appear in traces, and the app had no trace ID to correlate its logs with. This affected HTTP, gRPC, bulk and streaming subscriptions.

### Root Cause

The HTTP and gRPC delivery paths only started a span when the CloudEvent carried a `traceparent` or `traceid`. With neither present, no span was started.

### Solution

The sidecar now always starts a span for a pub/sub delivery when tracing is enabled. With no inbound trace context it starts a new root span, and the app receives its `traceparent` header. Messages that previously had no trace now start a new one, so expect new traces in your tracing backend. Nothing changes when tracing is off in the Configuration.
